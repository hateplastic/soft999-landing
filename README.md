# Soft 99.9 — лендинг

Отдельный сайт продукта: neon UI, интерактивное превью, анимация демонстрационного комментария, Free/Pro, кабинет Supabase. Модули Telegram/X и локальные профили сюда не входят. Все события в превью — явно обозначенная демонстрация.

## Локальный запуск

Нужен Node.js 20+. Зависимостей npm нет.

```sh
npm run dev
npm run check
npm run build
```

Предпросмотр: http://127.0.0.1:4173. Публикуется только `dist/`. Можно запускать `START-PREVIEW.cmd`: он открывает страницу в браузере и автоматически находит локальный ZIP в соседней папке `Soft 99.9/release`, если он есть. Для остановки сервера — Ctrl+C в окне запуска.

Для проверки скачивания локального ZIP задай `SOFT999_PREVIEW_RELEASE` абсолютным путём к релизу перед запуском dev-сервера. Архив раздаётся только на loopback, не копируется в сайт и не входит в сборку. Без этой переменной локальная кнопка показывает состояние подготовки загрузки.

## GitHub → Vercel

1. Создай отдельный GitHub-репозиторий и загрузи файлы ЭТОЙ папки. Не добавляй соседние проекты, профили, базы, ключи и архив клиента. GitHub Release для клиента публикуется отдельно после проверки содержимого архива.
2. Подключи репозиторий в Vercel. Сборка и папка результата указаны в `vercel.json`: `node scripts/build.mjs`, `dist`. Install command можно оставить пустым. Сервер сайта не запускает Telegram/X.
3. Задай публичный HTTPS `downloadUrl` в `src/config.js` после публикации проверенного Windows-релиза. Сейчас публичная загрузка честно обозначена как ещё не открытая.
4. Подключи домен в Vercel и настрой DNS по выданным значениям. Домен пока не выбран.
5. В Supabase Authentication → URL Configuration добавь точный адрес сайта в Redirect URLs (для разработки `http://127.0.0.1:4173/`). Существующий адрес клиента не удаляй. Site URL должен стать публичным адресом продукта после запуска; проверь совместимость ссылок восстановления в клиенте.
6. Подключи собственную SMTP-доставку Supabase и подтверди домен отправителя. Без этого регистрация для всех пользователей не готова. Ключи SMTP вводятся только в Supabase, не в файлы сайта.
7. Примени `supabase/20261018_website_account.sql` через SQL Editor. Это чтение собственного тарифа без изменения привязки устройства. Если функция не установлена, кабинет честно покажет «Статус недоступен». Авторизация при этом работает независимо.
8. После настройки серверной проверки платежей Tribute и связи Telegram с учётной записью заполни `purchaseUrl`. Сама ссылка НЕ активирует тариф; срок оплаты обновляет доверенный серверный обработчик после проверки подписи события. Secret/служебные ключи никогда не помещаются в сайт.
9. Добавь контакты владельца, полную политику обработки данных и условия продажи перед публичным приёмом оплат.

## Кабинет

Email/пароль, регистрация, повтор подтверждения, восстановление и смена пароля через Supabase Auth. Токены только в памяти вкладки; перезагрузка требует входа. Ссылка восстановления очищается из адресной строки. Таблица прав закрыта от прямого чтения и записи; функция `soft_account()` возвращает только собственный тариф, срок и наличие привязки. Вызова `soft_access` на сайте нет: браузер не занимает слот Windows-устройства.

Публичный Supabase publishable key намеренно находится в `src/config.js`; он не является серверным секретом. Защиту данных обеспечивают права БД и Auth. Никаких service_role, секретов бота или платёжных ключей здесь быть не должно.

## Перед выпуском

- Проверить регистрацию внешнего email, подтверждение, вход и восстановление на конечном домене после SMTP.
- Проверить Free/Pro/истечение подписки и отсутствие изменения device_hash при входе на сайте.
- Указать реальный URL загрузки; просканировать архив на личные аккаунты, сессии, токены и базы перед его публикацией.
- Выполнить реальную тестовую оплату после Tribute, проверить однократную обработку повторных событий и отмену подписки.
- Проверить Windows-клиент на чистом ПК: это portable ZIP, не готовый .exe-установщик.

Оригинальные скриншоты с email/именем пользователя/идентификатором устройства не опубликованы. Интерфейс воссоздан средствами HTML/CSS. Здесь нет аналитических трекеров, чужих отзывов или вымышленных обещаний трафика.
